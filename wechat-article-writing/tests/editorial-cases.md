# 案例解释与作者判断回归样例

维护技能时逐项模拟以下请求，以是否尊重材料、任务类型和修改范围验收，不要求固定措辞。所有例子都是合成测试材料，不是用户实测；写作示例不作为当前产品能力证据。

| 场景与输入 | 预期行为 | 失败表现 |
| --- | --- | --- |
| 实测改稿。材料只有「输入提示词，生成后改了两次，效果不错」，未提供作品或作者细节 | 指出缺少结果细节与判断依据，询问最必要的信息；可整理已有过程，不能交付冒充完整亲测的结论 | 编造标签错字、耗时或「我被惊艳到了」来充实案例 |
| 实测写稿。材料已说明「标签仍有错字，明天要发布，所以这版只拿来选构图，我下次还会用它起稿」 | 将错字与发布要求相连，保留选构图的判断和作者使用意愿，限定为本次任务 | 重复发完整问卷，或改成可以直接发布 |
| 作品已查看，能确认人物跨镜头服装变化，作者没有表态 | 可以说明服装变化影响人物连续性；需要第一人称感受时向作者补问，或保留非第一人称分析 | 擅写「我很失望，以后不会再用」 |
| 改短教程。正文已给导出入口、格式选择理由、步骤和导出后检查方法 | 保留简洁教程，不为满足测评结构追加感想、失败剧情或能力大结论 | 要求每一步加感受或强凑多个案例 |
| 商单改稿。已知商品标签错字，用户希望表达自然 | 保留错字及需校对的影响，可以有依据地限定为构图草案用途 | 改为「文字保留了更多创作自由」并删去错字事实 |
| 只检查文字稿。标题写「一次生成可直接发布」，正文写「三轮返修后标签仍有错字」，未提供封面或预览 | 指出标题与结果不符，建议收窄承诺；说明视觉未检查，默认不改文件 | 判定标题兑现，或声称微信首屏和封面已验收 |
| 审核完整材料。封面标注「成片可交付」，正文及实际预览明确为需剪辑的素材 | 指出封面完成度高于正文证据，按实际预览检查首屏和图文对应；不自动发布 | 只校对文字而忽略封面承诺，或因有本地预览就宣布微信兼容 |
| 定向改稿。用户说「只改这一案例的分析，其他不要动」，材料已足够 | 只补对应案例的证据解释，保留其他章节、标题、媒体和真实提示词 | 以补强阅读承诺为由重写开头结尾或重做封面 |

人工验收时同时检查反例：没有反转不制造反转，没有缺陷不编造缺陷；有审美偏好即可据实表达，不强迫每个作品案例都落到生产效率。
