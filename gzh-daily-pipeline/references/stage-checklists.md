# 各阶段自查清单

每阶段交付前逐条核对。清单用于发现问题，不用于凑格式。

## S0 定盘

- [ ] 受众定位是一句话，不是「所有人」
- [ ] 聚焦领域 3 到 6 个，本次选题落在其中
- [ ] 常青备胎选题至少 2 条可查
- [ ] 人设卡写了绝不提什么
- [ ] 风格 DNA 有禁用词清单
- [ ] 往期文章库列了 3 到 5 篇可模仿样本

## S1 选题

- [ ] 候选选题之间是不同问题，不是同一想法换标题
- [ ] 每个候选都有来源、证据边界、新增价值和待核条件
- [ ] 至多3个候选，不凑数；已比较读者价值与执行成本，不用统一分数放行
- [ ] 选定选题的理由写清，放弃的条件也写清
- [ ] 说明时间价值或常青价值，不强蹭热点
- [ ] 首选有最小试跑；前提失败可退回S1，不预写实测结论
- [ ] 原料中的数字、日期、引文都有出处

## S2 案例与实测

- [ ] 案例决策卡的 8 个部分都填了，未满足条件写明缺什么
- [ ] 读者问题不是「这个工具怎么样」
- [ ] 案例有读者愿意看的事，也有明确的观察目的
- [ ] 合成测试数据已标注，不伪装成真实客户或经历
- [ ] 验收标准可观察，不是「看起来不错」
- [ ] 实测记录分开了首次结果、失败、修改、再次结果和人工接手
- [ ] 耗时与费用分开记录，没有混算

## S3 写作

- [ ] 主问题清楚，每个案例贡献新信息
- [ ] 结构与材料匹配，没有硬套固定模板
- [ ] 读者较早看到值得读的成果或发现
- [ ] 关键判断都有观察或来源支持
- [ ] 第一人称、数字、时间、图片描述都真实
- [ ] 待补素材用 `【待补：…】` 标出，没有编造链接或截图
- [ ] 没有为凑篇幅重复夸赞或堆术语

## S4 定稿检查

- [ ] 错字、病句、标点、强调标记已查
- [ ] L1 禁用词、L2 标点、L3 句式、L4 活人感逐层过
- [ ] 实测表述区分了作者操作、模型自报、官方描述、推测和个人感受
- [ ] 数字、日期、价格、名称、入口的来源清楚
- [ ] Markdown 围栏、强调标记、图片视频引用完整
- [ ] 标题承诺与正文兑现一致
- [ ] 必须修改项已清零，待核实项已单列

## S5 标题封面排版

- [ ] 标题提供少量不同角度，选定标题与正文证据一致
- [ ] 标题不含绝对化用词，不虚构结果和数字
- [ ] 封面是 900×383，缩略图尺度能看清对象和动作
- [ ] 封面只保留一个视觉主语，承诺不超过正文证据
- [ ] 排版只翻译格式，没有改动一个字
- [ ] `.report.json` 的警告原样保留并说明
- [ ] 已说明本地预览不等于微信验收通过

## S6 发布与回流

- [ ] 预览首屏、图文对应和手机阅读效果已确认
- [ ] 发布记录含平台、发布时间、阅读、留言和异常
- [ ] 成稿已写成知识库 source 页，来源路径真实存在
- [ ] 受影响的 concept、entity、topic 页已更新
- [ ] `wiki/index.md` 与 `wiki/log.md` 已更新
- [ ] `python scripts/wiki_lint.py` 无错误
