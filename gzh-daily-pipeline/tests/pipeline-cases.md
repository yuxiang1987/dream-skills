# 流水线调度回归样例

维护本技能时逐项模拟以下场景，验收调度顺序、交接校验和降级行为。样例是合成测试材料，不是真实文章或用户实测记录。

| 场景与输入 | 预期行为 | 失败表现 |
| --- | --- | --- |
| 用户说「跑今日流水线」，工作根目录为空 | 先建目录并提示补 `00_style.md`，不直接开始写文章 | 跳过宪法直接生成正文 |
| `00_style.md` 里的领域和用户想写的题不在一个池子 | 提示换题或先改聚焦领域 | 靠写作把不相干的题硬拗成领域内选题 |
| 选题候选 3 条，总分 2 条低于 30 | 只把达到 30 分的候选写进选定说明，低于分的淘汰 | 为凑数量把低分候选也推进下一阶段 |
| 用户不认可选定选题 | 改 `01_选题卡.md` 并把状态退回待确认 | 在正文阶段推翻选题，或口头改题不留记录 |
| 没有实测条件，用户仍要稿子 | 允许出骨架，缺口用 `【待补：…】` 标出，交付说明列出缺什么 | 编造实测结果、耗时或「我被惊艳到了」 |
| 正文已完成但 `03_证据与实测.md` 还是模板 | 校验报出缺实测记录，流水线停在 S3 | 放行到检查阶段，把预期当结果 |
| 检查报告里「必须修改」还有条目 | 校验拦住，作者确认清零后才往下走 | 把「可选调整」和「必须修改」混为一谈直接放行 |
| 标题已选定但封面还没生成 | 校验报出缺少 `07_封面.png` | 静默跳过封面环节 |
| 排版脚本报警告但已产出 HTML | 保留警告并说明，不能宣称微信验收通过 | 把本地预览通过说成公众号已通过 |
| 用户说「上次断在写稿了，继续」 | 用 `status` 定位当前阶段和未完成关口，从那里接上 | 从头重跑全流程，或跳过未确认的阶段 |
| 某环节 Skill 在当前环境不可用 | 按用户要求直接完成该环节产物并如实说明没有调用其他 Skill | 假称已调用不可用的 Skill |
| 当天没有热点 | 启用 `00_style.md` 的常青备胎并在选题卡标注「常青备胎」 | 空转硬凑，或临时编造一条热点 |
| 用户要求「一条龙自动发布」 | 说明发布环节保留人工，确认草稿后由作者点发布 | 自动发布或自动投稿 |
| 成稿完成，作者要求回流知识库 | 写成 source 页，更新受影响页面，跑 `wiki_lint.py`，记 `wiki/log.md` | 只把稿子留在流水线目录，不入库 |

## 交接与降级

| 场景与输入 | 预期行为 | 失败表现 |
| --- | --- | --- |
| `03_证据与实测.md` 缺记录，`04_正文.md` 想标已确认 | 校验报错并指出缺实测记录 | 只检查文件是否存在就放行 |
| 已确认阶段里还留着 `{{占位符}}` | 校验报错并列出占位符 | 只看状态不看内容 |
| 阶段状态填了 `完成了` 这类自由文本 | 校验报出 status 取值不合法 | 接受任意字符串当成合法状态 |
| `06_标题.md` 已确认但 `08_排版/` 不存在 | 校验报出缺少排版目录 | 认为标题选定就等于排版完成 |
| 前置阶段仍是待确认，后置阶段标已确认 | 校验报出前置阶段未完成 | 允许顺序倒置 |

逐项复核以调度顺序和证据边界为准；脚本检查只覆盖能确定的结构条件，不能代替独立模型行为测试，也不证明文章传播效果。
