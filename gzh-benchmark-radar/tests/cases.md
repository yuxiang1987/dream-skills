# 对标雷达行为验收

每个案例实际跑脚本或加载技能产出后逐项核对；不以"搜到相同措辞"代替行为验证。所有示例为合成输入，不是用户实测数据。

| 输入场景 | 应有行为 | 失败信号 |
| --- | --- | --- |
| 首次运行，未配置凭据 | `fetch` 明确报「未找到凭据」并停下，不尝试匿名请求 | 静默失败、或把 key 写进任何文件 |
| 只想看状态 | 用 `plan`，输出各号原文数、已入库数、未入库数；不发网络请求 | 直接跑 fetch 产生扣费 |
| 同一篇文章已在 raw 里 | 跳过，`skipped_existing` 加一，不改原文件、不另存副本 | 覆盖旧文件或生成重复副本 |
| 同一篇文章改过内容 | 另存新快照，保留旧文件，文件名带正文指纹 | 覆盖旧快照、丢失历史版本 |
| 账号清单里写了非 `gh_` 的用户名 | 采集前报错并停止，不拿默认账号硬采 | 采到别的号、把身份核验跳过 |
| 分页返回的账号与目标不符 | 立刻停止并报错 | 继续采，混入别的号文章 |
| 统计接口部分失败 | 报告成功与失败数，失败项留 error，不填 0 | 用 0 当缺失值算基线 |
| 某号只有 2 篇有效数据 | 仍给出中位数但标 n=2，提示样本过小；不据此下结论 | 用两篇推"该号日常水平" |
| 一篇阅读是号内中位数 2.3 倍 | 列入异常样本并给倍数，同时写清单次快照、含系统推荐、10 万封顶 | 称"爆文"、或推断某个标题导致传播 |
| 两个号各写同一产品 | 聚成一条事件簇，覆盖账号数与跨度列出 | 出两条同题候选 |
| 只有一个号连写同一产品三篇 | 不形成跨账号事件簇，按系列文处理 | 把单号系列当热点事件 |
| 未入库原文 | 出现在 `raw_without_source` 清单 | 声称已拆解、已入选题池 |
| 文章里有实测与步骤信号 | 生成案例卡候选，`models`、`signals` 填好，`angle`/`steps`/`checks` **留空**待填 | 脚本代写测试角度与结论 |
| 案例卡合并进案例库 | 按现有分类插入，字段齐全，缺的写"未提供"，标待实操 | 新建平行库、复述全文、把作者结果当我们的实测 |
| 评论需求只有 1 条 | 写"需求假设"，不当普遍需求 | 写成"很多读者问" |
| 评论需求 ≥3 条 | 可作读者真实问题，附原话与条数 | 只给结论不给原话 |

脚本回归见 `tests/test_ingest.py`（离线、不发网络请求）。判断类质量（类型分得对不对、优先级排得合不合理）需要人工抽查，脚本不代替。
