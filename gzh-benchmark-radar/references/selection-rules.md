# 候选口径：类型、结构、时效与优先级

本文件是 `gzh-benchmark-radar` 输出候选时的判断依据。风格与硬规则以 `gzh-topic-planning` 为准，这里只补"数据到手之后怎么落成候选"。

## 一、类型：六类内容方向

| 类型 | 判据 | 例子 |
| --- | --- | --- |
| 实践型 | 自己动手做出成品或完成一个项目 | 两天搭出门户网站；一个人干完视频团队的活 |
| 解决问题型 | 先有反复出现的具体麻烦，再用工具解决 | 月报 PPT 从一天压到 20 分钟；总忘关共享单车做个小工具 |
| 整活型 | 荒谬有趣、自设实验或沙盘，不以效率为目标 | 和名人一起吃饭拍电影；股票智囊团一个月亏 20% |
| 教程型 | 以可复现步骤为主线，读者照着能走通 | 0 基础安装指南；一步步做炒股网站 |
| 观点型 | 解释为什么、判断趋势与差异，主要交付判断 | 为什么 A 能超越 B；国内和海外差距还有多大 |
| 资讯型 | 以发布、更新、榜单等消息为主线 | 某模型发布新功能 |

- 只选一类，不混写。方向决定写什么；结构（同素材对照、难度递增测试等）由写作技能在写稿阶段定，不必写进候选。
- **资讯型不写纯转述**：必须落到「这对我们读者意味着什么」，落不住就不出这个候选。

## 二、热点：只用两个值

- **热点**：跟发布、榜单、活动节点走，有明确窗口；过期就不写。有具体截止日时在候选块下补一行 `截止：YYYY-MM-DD`。
- **长青**：方法、结构、验收思路这类不随版本失效的。

版本绑定类型的条目先核当前版本，核不到就降为条件候选，不当成可写题推荐。

## 三、优先级：字典序，不打总分

先过硬门槛，任何一条不过直接淘汰：

1. 题材对得上三条主线（AI Coding、Agent 工作流、AI 视频）；面试问答、薪资职级、人物八卦、纯资讯转述一律不进。
2. 时效没死。
3. 核心前提可靠（产品还能用、版本对得上、能力不是只靠官方说法）。
4. 相对已发稿有新增问题或证据。
5. 材料在手，或缺口可解决（需权限与额度的列为条件候选，不能挤掉能做的）。

过关之后按固定顺序比，不做加权分数：

1. 同事件是否已发过——写过就不出，除非有新证据。
2. 材料是否在手——自有素材优先于需权限。
3. 时效窗口——快过期的优先，常青排后。
4. 与已发的差异度——差异越具体越靠前。
5. 判定成本——半小时能出结果优先于需要一周。

顺序可以讨论后改；不要改成加权总分，那会把"材料根本拿不到"这种硬问题掩盖掉。

## 四、数据怎么进判断

- **异常样本**（≥2× 本号中位数）说明该号读者群对这题关注度高，可提高同一事件候选的优先级；但它是单次快照、含系统推荐，不能推因果。
- **事件簇**里篇数多、跨度短的事件，说明是当期热点；只在窗口内有效。
- **评论需求**：同一需求出现 ≥3 条才算重复追问，可以当读者真实问题；只出现 1 条的写"需求假设"，不能写成"很多读者问"。评论只代表评论者，不代表全体读者。

## 五、不做的判断

- 不用"对标阅读高"直接推"我们也该写"。
- 不用"某个标题涨了"推"这个标题结构有效"。
- 不因为自动采到了素材就宣布已拆解、已实测或已选定。
