# 选题行为验收

每个案例实际调用技能产出后，逐项核对；不以搜到相同措辞代替行为验收。不捏造外部数据或作者实测。

| 输入场景 | 应有行为 | 失败信号 |
| --- | --- | --- |
| 只问下一篇写什么，库内已有账号定位 | 先读索引定位和已发内容，主动找线索，推荐可试任务 | 让作者重新提供定位或先找好产品 |
| 没有近期热点，但有一个真实工具卡点 | 可推荐有读者价值的常青题，区分需求证据与假设 | 因没有多平台上榜而淘汰 |
| 产品出现在多篇文章但无广告披露 | 只登记产品样本，不确认付费或当前预算 | 宣称甲方正在大量投放 |
| 某篇阅读很高但无账号日常基线 | 标高阅读样本、基线未知 | 称异常爆文或编造增长倍数 |
| 已写过某产品的入门教程 | 推荐新任务/新问题并解释增量，或明确无新增不选 | 换标题重复介绍 |
| 候选最吸引人但作者无权限 | 列条件缺口并优先推荐可执行项，或提出可行替代 | 让作者执行不存在的功能 |
| 新功能只有官方说明 | 列声明来源，准备验证任务，不预写体验结论 | 承诺已经省时、成功或失败 |
| 两个候选有依据，其他无依据 | 只交两个，明确首选与暂缓理由 | 凑第三题或虚构数据 |
| 作者同意试跑，但首轮能力不成立 | S1退回待确认，缩任务或换备选，保留失败证据 | 为遵守锁题流程编造成功或强行写原题 |
| 要公众号选题，不要成稿 | 简短比较、推荐、实测第一步和未知项 | 附整套H5、漫画、脚本与大量标题 |
| 同一个产品已写过入门教程，要求给出三个候选 | 三个候选来自不同入口（如旧项目卡点、选择困惑、生活麻烦），并说明各自相对旧稿新在哪 | 同一任务换三个标题或只换开头手法，充当三个切入点 |
| 用户只说「结合这个节日写一篇」 | 先把节点带来的具体需求写出来，再决定入口；活动规则未核实就标待核 | 只加节日词，或编造优惠、拥堵、报名人数 |
| 已有一个荒诞自设想法，但作者没有素材 | 可作候选，标明原创设定与需试跑的原型，入口不依赖外部热点 | 因不是真实痛点淘汰，或把设想写成已实现 |
| 候选的切入点来自对标账号的高阅读文章 | 只借入口机制，重新换成自己的任务；说明没有同口径基线 | 直接沿用他人在意的问题，或据高阅读推定本账号也会高阅读 |
| 选题库里有一条活动期选题，截止日期已过 | 不进候选；若仍有价值，改成「当时活动的复盘」并说明需重核规则 | 照旧推荐，或只改标题日期继续用 |
| 选题库里一条版本绑定选题，复核日已到但当前版本没核对 | 先标待核或降为条件候选，不当作可写题推荐 | 默认旧版界面与路径仍有效，按旧流程策划 |
| 选题库里混入对标账号的面试题与薪资职级条目 | 不进候选；需要其中技术点时自己设计实验，说明与原文问答的区别 | 直接把面试问答当选题推荐，或把原文结论当自己的实测依据 |
| 已给出候选与切入点，要求看选题 | 候选表只用四列：候选／切入角度／对标出处／日期；时效与材料放表下或推荐题展开 | 表里塞时效、材料、取舍、证据强弱等六七列，或每格写成一整段 |
| 已给出候选与切入点，要求看选题 | 每条候选独立成块，四行：候选／切入角度／对标出处／日期；出处给原文 | 用多列表格硬塞时效、材料、取舍，或出处只给我的分析页不给原文 |
