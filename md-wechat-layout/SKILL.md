# 公众号排版

雾蓝气泡默认使用系统无衬线字体：苹方／微软雅黑及系统字体回退，正文与标题统一，代码窗口继续使用等宽字体。字号、行距不因换字体改变。不同设备的实际字体可能不同。

薄荷气泡精修：正文左对齐；含加粗的普通段落改用深灰文字与浅绿左边线表达重点，保留全段统一字号；列表沿用已验证的兼容处理。小节虚线减淡，表格文字 14px、行高 26px，单元格最小宽度 5.5em；图片阴影减轻。预览页长围栏代码窗口限高 450px 并纵向滚动，此限制仅在预览 CSS 中，复制 HTML 保留完整展开内容，避免微信中隐藏长提示词。源文不删减。

薄荷气泡小节标题使用同字号的空心四芒星 ✧ 文字，不用缩小字号的装饰 span；标题字号和行高显式使用 px，保留绿色与虚线。此适配来自微信对小节标题的实际警告，仍须区分本地检查与微信粘贴验收。

使用本 skill 自带的上游渲染器和主题，不凭印象重写 CSS。不声明主题时默认「雾蓝气泡」（mist-blue，别名雾蓝），使用薄荷气泡的兼容布局与低饱和蓝色配色。含加粗的普通段落使用浅蓝底 #F0F5FA、1px dashed #B8CEE2 边框、6px 圆角、12px 16px 内边距，深灰正常字重。用户可显式选择「薄荷气泡」绿色版或「青山绿水」；「青绿山水」与「青山绿水」同义。

微信兼容适配：青绿山水的文字标题背景使用同色系纯色，不使用渐变；保留无文字分隔线的渐变。文本显式设置合理行高。不得添加检测豁免标记来隐藏问题。首次交付或收到结构警告时，优先用微信官方 `wechatjs/verify-article-structure-spec` 的 CLI 检查正文 HTML（非带 UI 的预览页），区分原始 HTML 检测结果与实际粘贴后的结果。

参考资料编号使用同字号、同基线的普通 `[1]` 文字，避免缩小并上移的角标在粘贴后产生行高风险。若本地通过但微信仍警告，不得宣称微信问题已解决；继续根据实际警告定位粘贴后的节点。

正文含局部加粗时，兼容输出将其提升为整段强调，移除段内 strong 外壳，保留全部文字。此处理源于实际微信粘贴警告：普通文字与加粗混排段落在本地通过但微信报行高风险，整段强调曾经用户验证通过。交付时说明强调范围扩大，不把本地通过当成微信实测通过。

列表项也显式设置字号和行高，局部加粗提升为整项强调，项目符号直接作为文字，不另加 span。Obsidian 中加粗结束符紧贴中文时，渲染前补一个分隔空格以正确解析，代码中的星号保持原样。

用户的微信兼容输出将行内代码和链接转换为普通显示文字，不输出 code/span/a 外壳或行内代码背景，不保留链接点击功能；保留文字内容，源 Markdown 不变。此处理覆盖全文及列表，解决统一字号后仍出现的混排警告。独立围栏代码窗口仍用等宽字体。高亮和其他行内文字统一字体尺寸与基线。

用户的固定版式偏好：图片四角统一 6px 小圆角，附柔和立体阴影 `0 5px 16px rgba(35,65,55,0.16),0 1px 4px rgba(35,65,55,0.08)`，不显示附件文件名图注；显式写出的描述性图注仍保留。合成拼图只对整图外角应用圆角，内部分图边角属于原图像素，不能靠 CSS 改变。围栏代码块使用白色主体、浅灰标题栏、三色窗口按钮和语言标签的浏览器窗口外观，长行自动换行。保留主题的正文配色与字体。

## 执行

1. 确定用户提供的 Markdown 文件。只有无法从上下文定位文章时才询问路径。按原文排版，不修改源文件、标题或正文。Obsidian 附件可传 `--vault`；不要猜测库位置或任意选择重名附件。
2. 在 skill 目录检查 `node_modules`，缺少依赖时执行 `npm ci`。需要 Node.js 18+。如果 `node` 不可用，检查可用的 workspace runtime，不自动安装系统软件。
3. 从 skill 目录执行（使用绝对输入和输出路径）：

   ```powershell
   node scripts/render.mjs "D:/Obsidian/文章.md" --vault "D:/Obsidian" --out "输出目录"
   node scripts/render.mjs "D:/Obsidian/文章.md" --theme "薄荷气泡" --vault "D:/Obsidian" --out "输出目录"
   ```

   默认 16px，保留主题字体，单列图片，原文链接仅保留显示文字，不自动新增参考资料。只有用户要求外链转参考资料时才传 `--link-footnotes`；可用 `--font-size 18` 调整字号。默认输出文章旁的 `wechat-output`；遵守当前可写目录限制，必要时显式传入工作区输出目录。再次运行会覆盖同名输出，需要保留版本时换目录。
4. 检查 `.report.json` 的警告和生成的 `.wechat.html`。本地图片缺失、路径歧义、未知主题会报错，应修正后再生成。首次用于真实文章或版式明显变化时，用可用浏览器查看 `.preview.html`，重点检查标题、代码、表格和图片。未检查或未实测微信公众号时如实说明。
5. 返回预览页和 HTML 的绝对文件链接，说明使用的主题及与当前文章相关的警告。有合适的打开工具时展示预览；Windows 可用 `Start-Process -FilePath "预览文件绝对路径"` 在默认浏览器打开。用户点击「复制公众号排版」，再在公众号草稿正文粘贴。**复制 HTML 源码文本不会获得排版**，不可把 `Set-Clipboard` 纯文本当成富文本复制成功。按钮失败时选中预览中的文章正文并 Ctrl+C。

## Obsidian 兼容范围

- 去掉文首 YAML 属性和 `%%注释%%`，保护代码中的 Obsidian 记号。
- `[[笔记|文字]]` 转显示文字；不读取其他笔记内容。
- `![[图片.png]]`、普通 Markdown 本地图片转换为 data URI；支持 PNG/JPEG/GIF/WebP。库内重名图片须指定明确路径。图片尺寸别名不强制保留。
- Callout 转普通引用并保留标题；折叠行为不保留。
- 笔记嵌入和其他附件用提示文字替代并报告；Dataview、Obsidian 插件块和数学公式不执行。遇到这些内容，应检查原文，按用户需求处理或明确指出未转换。
- 图片 data URI 与外链图片能否在微信中转存必须在粘贴后确认。不能把本地预览成功当成微信验收成功；失败时在公众号后台上传图片替换。视频也应在公众号后台插入。

上游来源及许可证见 [references/upstream.md](references/upstream.md)。脚本输出的正文均为内联样式；预览页 UI 不进入复制内容。不替用户登录、保存草稿或发布。
