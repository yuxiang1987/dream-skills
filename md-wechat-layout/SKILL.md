# 公众号排版

默认主题「晴蓝手记」（`blue-journal`，别名「洛洛蓝」）：参考洛洛AI说文章的白底、黑字、居中小节标题和大号斜体章节编号，按用户要求改成蓝色。二级标题自动编号，`==高亮==` 使用浅蓝底，普通加粗仍为黑色粗体。未指定主题时自动使用，也可显式传入 `--theme "晴蓝手记"`，细节见 [晴蓝手记](references/blue-journal.md)；不改源文，不自动选择高亮文字，用户指定其他主题时按其选择执行。

晴蓝手记采用与参考文章一致的微信系统字体栈，默认15px正文、25.5px行高（1.7倍）、1px字距；章节编号使用亮天蓝 `#8dd6ff`，高亮恢复为浅蓝底 `#e8f7ff`。最后一个二级标题上方自动显示 `END`，默认56.25px，比67.5px数字编号小一档，原文标题文字保留。图片取消92%比例限制和4%内边距，恢复width:auto、max-width:100%的原比例自适应显示；外层使用独立section与border-box，左右margin为0、padding各32px，显式text-align:center；图片用inline-block并保留margin:auto，不继承正文段落的左对齐与边距。单图、单列图库及混排图片均保持比例与对称留白。本地不放大小图，保留比例、圆角和阴影。该适配须实际重贴到微信草稿验证，不能把本地模拟通过视为微信已通过。提示词及代码窗口顶部用浅蓝底 `#e1f3ff` 与蓝色标签，窗口正文保持白底。正文与标题继承主题字体，数字编号和代码窗口保留各自字体；实际字形随设备字体回退变化。

雾蓝气泡默认使用系统无衬线字体：苹方／微软雅黑及系统字体回退，正文与标题统一，代码窗口继续使用等宽字体。字号、行距不因换字体改变。不同设备的实际字体可能不同。

薄荷气泡精修：正文两端对齐、末行左对齐；普通段落中的 Markdown 加粗保留为行内粗体，不升级为左边线或引用样式；列表沿用已验证的兼容处理。小节虚线减淡，表格文字 14px、行高 26px，单元格最小宽度 5.5em；图片阴影减轻。围栏代码与提示词窗口默认最高320px，超出后纵向滚动；限高和overflow:auto写入正文内联样式，正常与备用复制均携带这些样式及完整内容，不仅改预览CSS。`--code-max-height 0`可导出完整展开版，其他非负数可调整高度。微信可能改写样式，未经粘贴、重载和手机预览，不宣称平台滚动已通过；若出现内容裁剪而不能滚动，应改用完整展开版。源文不删减。

薄荷气泡小节标题使用同字号的空心四芒星 ✧ 文字，不用缩小字号的装饰 span；标题字号和行高显式使用 px，保留绿色与虚线。此适配来自微信对小节标题的实际警告，仍须区分本地检查与微信粘贴验收。

使用本 skill 自带的上游渲染器和主题，不凭印象重写 CSS。不声明主题时默认「晴蓝手记」（blue-journal，别名洛洛蓝）。「雾蓝气泡」（mist-blue，别名雾蓝）仍可显式选择，使用薄荷气泡的兼容布局与低饱和蓝色配色。普通段落中的加粗只改变对应文字的字重和颜色；只有 Markdown 显式引用 `>`、Callout 转换结果等引用内容才使用卡片或引用样式。用户可显式选择「薄荷气泡」绿色版或「青山绿水」；「青绿山水」与「青山绿水」同义。

微信兼容适配：青绿山水的文字标题背景使用同色系纯色，不使用渐变；保留无文字分隔线的渐变。文本显式设置合理行高。不得添加检测豁免标记来隐藏问题。首次交付或收到结构警告时，优先用微信官方 `wechatjs/verify-article-structure-spec` 的 CLI 检查正文 HTML（非带 UI 的预览页），区分原始 HTML 检测结果与实际粘贴后的结果。

参考资料编号使用同字号、同基线的普通 `[1]` 文字，避免缩小并上移的角标在粘贴后产生行高风险。若本地通过但微信仍警告，不得宣称微信问题已解决；继续根据实际警告定位粘贴后的节点。

正文中的局部加粗和整段加粗均保留 `strong` 语义，不得将其提升为整段强调、左边线或引用卡片。加粗样式须继承正文的字号、行高和基线，降低微信粘贴后的混排行高风险；本地通过仍不能替代微信公众号粘贴验收。

列表项也显式设置字号和行高，局部加粗提升为整项强调，项目符号直接作为文字，不另加 span。Obsidian 中加粗结束符紧贴中文时，渲染前补一个分隔空格以正确解析，代码中的星号保持原样。

用户的微信兼容输出将行内代码和链接转换为普通显示文字，不输出 code/span/a 外壳或行内代码背景，不保留链接点击功能；保留文字内容，源 Markdown 不变。此处理覆盖全文及列表，解决统一字号后仍出现的混排警告。独立围栏代码窗口仍用等宽字体。高亮和其他行内文字统一字体尺寸与基线。

用户的固定版式偏好：图片四角统一 6px 小圆角，附柔和立体阴影 `0 5px 16px rgba(35,65,55,0.16),0 1px 4px rgba(35,65,55,0.08)`，不显示附件文件名图注；显式写出的描述性图注仍保留。合成拼图只对整图外角应用圆角，内部分图边角属于原图像素，不能靠 CSS 改变。围栏代码块使用白色主体、浅灰标题栏、三色窗口按钮和语言标签的浏览器窗口外观，长行自动换行。保留主题的正文配色与字体。

## 阅读排版规则

按用户《公众号文章格式》中的第 1、2、3、6、7、8、9 条执行；第 4、5、10 条不纳入本次规则，不据此改标题编号、限制配色或删除标题句号。

- 标题与标题、标题与正文之间至少留一行的视觉间距；文字与图片上下留白。HTML 用内联边距表达，不堆空段落或 `<br>` 撑间距；保留主题的章节编号与图片两侧留白。
- 正文首行不缩进，去掉段首用于缩进的全角空格或不换行空格；普通段落、列表和引用文字显式设white-space:normal，避免继承宿主编辑器的空白保留样式。中英混排间距仍用普通半角空格，不用nbsp或隐藏字符代替；代码缩进及提示词换行保留，防孤字段尾的nowrap仅作用于短尾组。截图只提示位置，不能据此断定微信把空格改成了哪种字符。
- 导出时把普通文字中的中文双引号 `“”` 转为 `「」`；汉字与相邻英文、数字之间补一个半角空格，已有空格不重复添加。覆盖标题、正文、列表、引用、表格和链接显示文字，跨加粗等行内标记仍处理间距。代码内容、网址目标、图片路径保持原样，不把英文直引号当中文引号替换。
- 段落以手机预览下两三行为宜，三四行时检查能否在语义边界另起一段，尽量不超过五行。每段之间留一行视觉空白；行数随屏宽、字号变化，不能把 Markdown 源码换行数当成最终显示行数。
- 正文普通段落统一两端对齐（`text-align:justify`），段落最后一行左对齐（`text-align-last:left`），自然换行；图片容器仍居中，标题、列表、引用与代码保留各自对齐方式。不用空格或硬换行补齐右边界，也不把孤字尾行等同于多余回车。两端对齐会分配行内间距，末行可能较短，实际断行随屏宽变化。
- 默认不绑段尾。`--avoid-orphans` 是保留的可选不拆行组，会把段尾4至6字及标点一起移到下一行，也可能扩大上一行留白；仅用户明确要求这种取舍时启用，不用于处理右侧参差，不能承诺微信保留或消除所有孤字。
- 先检查原文与手机宽度预览。长段仅在完整句子或明确转折处拆分到临时排版副本，不删改措辞、不拆散代码、提示词、列表项、表格或完整引文；无法安全拆分时报告位置和原因。渲染器不按固定字数自动断段，也不宣称自动完成了语义检查。源 Markdown 始终保留。

## 执行

1. 确定用户提供的 Markdown 文件。只有无法从上下文定位文章时才询问路径。按原文排版，不修改源文件或改写正文；导出副本仅做上述字间距、引号与必要的语义断段。临时副本保留在文章旁以维持附件相对路径；当前目录不可写时，使用明确的 `--vault` 与可解析的图片路径。Obsidian 附件可传 `--vault`；不要猜测库位置或任意选择重名附件。
2. 在 skill 目录检查 `node_modules`，缺少依赖时执行 `npm ci`。需要 Node.js 18+。如果 `node` 不可用，检查可用的 workspace runtime，不自动安装系统软件。
3. 从 skill 目录执行（使用绝对输入和输出路径）：

   ```powershell
   node scripts/render.mjs "D:/Obsidian/文章.md" --vault "D:/Obsidian" --out "输出目录"
   node scripts/render.mjs "D:/Obsidian/文章.md" --theme "薄荷气泡" --vault "D:/Obsidian" --out "输出目录"
   node scripts/render.mjs "D:/Obsidian/文章.md" --theme "晴蓝手记" --vault "D:/Obsidian" --out "输出目录"
   ```

   长提示词默认 `--code-max-height 320`；不需要滚动时用 `--code-max-height 0`。正文默认两端对齐、末行左对齐，不额外传入 `--avoid-orphans`。默认 15px，晴蓝手记行高1.7倍；保留主题字体，单列图片，原文链接仅保留显示文字，不自动新增参考资料。只有用户要求外链转参考资料时才传 `--link-footnotes`；可用 `--font-size 18` 调整字号。默认输出文章旁的 `wechat-output`；遵守当前可写目录限制，必要时显式传入工作区输出目录。再次运行会覆盖同名输出，需要保留版本时换目录。
4. 检查 `.report.json` 的警告和生成的 `.wechat.html`。本地图片缺失、路径歧义、未知主题会报错，应修正后再生成。首次用于真实文章或版式明显变化时，用可用浏览器查看 `.preview.html`，重点检查标题、代码、表格和图片，并以约 375px 手机视口检查段落行数、段间及图文留白，必要时按语义调整副本后重渲染。回归验证运行 `npm test`，排版规则用例在 `tests/reading-typography.test.mjs`。未检查或未实测微信公众号时如实说明。
5. 用户要求完整排版时，重新通过本Skill一次生成完整预览和正文，默认交付一个完整复制入口，不让用户拼接局部修订页。保持原稿只读；按授权在排版副本开头加入已确认图片。若用户已在公众号插入视频，应说明替换全文后仍需在后台重新插入，不伪称本地占位是已嵌入视频。返回预览页和 HTML 的绝对文件链接，说明使用的主题及与当前文章相关的警告。有合适的打开工具时展示预览；Windows 可用 `Start-Process -FilePath "预览文件绝对路径"` 在默认浏览器打开。用户点击「复制完整公众号排版」，再在公众号草稿正文粘贴。**复制 HTML 源码文本不会获得排版**，不可把 `Set-Clipboard` 纯文本当成富文本复制成功。按钮失败时选中预览中的文章正文并 Ctrl+C。

## Obsidian 兼容范围

- 去掉文首 YAML 属性和 `%%注释%%`，保护代码中的 Obsidian 记号。
- `[[笔记|文字]]` 转显示文字；不读取其他笔记内容。
- `![[图片.png]]`、普通 Markdown 本地图片转换为 data URI；支持 PNG/JPEG/GIF/WebP。库内重名图片须指定明确路径。图片尺寸别名不强制保留。
- Callout 转普通引用并保留标题；折叠行为不保留。
- 笔记嵌入和其他附件用提示文字替代并报告；Dataview、Obsidian 插件块和数学公式不执行。遇到这些内容，应检查原文，按用户需求处理或明确指出未转换。
- 图片 data URI 与外链图片能否在微信中转存必须在粘贴后确认。不能把本地预览成功当成微信验收成功；失败时在公众号后台上传图片替换。视频也应在公众号后台插入。

上游来源及许可证见 [references/upstream.md](references/upstream.md)。脚本输出的正文均为内联样式；预览页 UI 不进入复制内容。不替用户登录、保存草稿或发布。
