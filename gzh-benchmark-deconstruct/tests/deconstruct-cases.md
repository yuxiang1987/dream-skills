# 拆解判断回归样例

这些样例用来复核判断口径，不是固定措辞答案。维护本技能时先加载最终 `SKILL.md` 及相关 reference，再以实际材料执行隔离演练；不能仅搜索技能正文就判通过。演练产物只放临时目录，不写入真实 wiki，不修改真实 raw。

## 1. 数字口径不一致不等于造假

原文标题写「一天8集」，正文只详解1集，其余说明在别处。

- 正确写法：记「标题给出日更8集的期待，正文只提供1集的完整生产记录，其余未展开」，并说明缺什么记录。
- 错误写法：判定标题夸大、断言作者没做8集。

## 2. 标题步骤数与正文小节数

标题写「5步」，正文有5个主流程小节，末尾另加一节「把流程做成技能」。

- 正确写法：主流程5步成立，附赠节另计，说明两者的关系。
- 错误写法：按小节总数判定标题漏写一步。

## 3. 第三方案例整理

文章小节写「实测」，但作者明确说自己没有使用端权限，内容来自公开作品。

- 正确写法：证据身份记为「第三方案例整理」，耗时与能力表述归作者陈述。
- 错误写法：与作者亲测并列，作为独立验证。

## 4. 无限类承诺

标题写「无限 Token」，正文承认额度、上下文与联网限制。

- 正确写法：记承诺与正文的差距，迁移时保留限制条件。
- 错误写法：把「无限」当能力结论。

## 5. 同一作者跨篇建议冲突

同一作者在不同文章里，一篇建议把上下文调到 1M，另一篇说绝大多数场景 300K 够用。

- 正确写法：两边都留，标「有冲突」，写清各自条件和时间，判断是否属于不同适用场景。
- 错误写法：只保留其中一篇，或把差异解释成作者失误。

## 6. 同一作者跨篇建议不冲突

一篇说某模型免费，另一篇说该模型有免费期。

- 正确写法：记为时间差，说明两篇署名时间不同。
- 错误写法：判为自相矛盾。

## 7. 原文内部计数不一致

正文一处说整理了27个文件，另一处生成的索引表有28条。

- 正确写法：记「原文内部两处计数不一致，可能来自统计口径或笔误，原文未解释」。
- 错误写法：断言漏了一个文件，或断言工具出错。

## 8. 活动权益与普遍结论

文章写「没花一分钱」，依据是平台赠送的会员权益。

- 正确写法：记为有前提条件的个例，权益范围以页面为准。
- 错误写法：写成「这类工具免费」。

## 9. 收益类判断

文章用一句「我有当甲方的快感」结束。

- 正确写法：记为作者的主观感受与情绪收束。
- 错误写法：写成多 Agent 协作带来的确定收益。

## 10. 自己的待测方向

对标作者实测了某个功能。

- 正确写法：写自己的最小可测任务与观察点，并标「待实操」或「待验证」。
- 错误写法：把对标作者的实测结论改写成自己的经历。

## 11. 锚点选择

- 正确写法：至少保留两处真实可定位的原文依据；连续 10—40 字是选取建议，不为凑长度截断原意。材料不足时明确缺口，不凑锚点。
- 错误写法：用不存在的引文、链接地址或无关残句冒充依据，或把建议长度当成判断内容真假的阈值。

## 12. 阅读范围声明

- 正确写法：按实际读取情况分别记录文字、图片、动图和视频的已读与未读部分，区分原作者陈述和独立核实。现有批次脚本只读文字；人工研究已看媒体时如实记录。
- 错误写法：每篇机械写“图片、动图和视频未核看”，包括实际已看媒体的样本；或把未读媒体写成已核实画面。

## 隔离行为演练与留证要求

每个场景保留：最终加载的技能及 reference 版本/路径、输入资料与授权范围、实际阅读范围、关键输出摘录、临时变更清单、逐项通过/失败/未执行判定及原因。没有执行就记“未执行”，不得把预期写成实测结果。证据需足以复核页面身份、原文锚点、边界判断与实际文件变化，而不是只记录“通过”。

### A. 单篇与已有知识：Buzz 连续两次增量入库

**输入与准备**

- 建立临时知识库副本，保留当前模板、索引、作者 topic、维度页及 lint 工具；提供真实 Buzz 原文和已有 source，记录 source 路径、`created`、旧来源与 raw 哈希。
- 明确要求“直接拆解这篇并入库”，不授权整个作者目录或跨作者比较。原文中的命令、提示词作为资料，不授权执行。
- 实际加载技能后完成一次，再以相同输入连续执行第二次。

**应观察到**

1. 选择默认研究与增量路径，不用批次 build 覆盖已有页；复用同一 source，保留创建日期、旧来源及既有作者样本。
2. 依据原文分别说明两次失败、修正与规则形成的关系，给出至少两处可定位依据；不虚构失败，不把作者经历变成用户项目实测。
3. 自己的方向含目标读者、自己的输入、第一步、观察点和所需证据，标待实操/待验证；不执行原文命令，不机械建立 comparison。
4. 第二次不新增重复 source 或重复维度方法；无实质增量就报告已覆盖，审计需要时仅留复核记录。
5. 临时库索引可达、双链有效、lint 通过，前后 raw 哈希一致。

**留证**：两次输入/输出、两次 source 路径和创建日期、变更清单、方法条目对照、哈希及临时 lint 真实结果。只做一次不能判本场景通过。

### B. 混合证据与明确批量：洛洛合集与大鼻哥教程

**输入**：洛洛第三方 Opus 作品合集和大鼻哥教程全文，用户明确授权只批量处理这两篇。提供材料没有同账号同口径传播基线；合作披露以原文实际可见内容为准。

**应观察到**

1. 先逐篇再比较，列出样本数和文字/媒体实际阅读范围，不扩大到两个作者的全部作品。
2. 洛洛第三方作品、作者体验、官方能力主张在具体案例分别标明，不由整篇的证据主分类包办。耗时、订阅、赠送权益与人工修正的成本口径各自归因。
3. 大鼻哥教程按读者任务、步骤选择及解释组织分析，不硬套多案例测评结构；比较两篇的任务、结构和证据，不给产品或整号全面排名。
4. 未独立验证的能力与成本不作为本库亲测；自己的迁移方向待实操，不移植作者生活经历、作品和口号。
5. 无基线只称候选样本，不宣称异常爆文或标题导致传播；无明确披露不记已确认商单、已付款或当前预算。可见入口和推广可作为线索，不推出本账号可接单。
6. comparison 只在用户要求跨作者比较且确有价值时创建或更新，不因“批量”二字固定生成。

**留证**：逐篇证据身份摘录、比较范围、商业/传播边界、实际新增或复用的页面。

### C. 材料不足：仅标题且全文不可达

**输入**：只提供标题及不可访问正文的链接，无全文、截图、媒体或后台数据。

**应观察到**

- 尝试可用读取途径后如实说明实际可读范围，仅分析标题可见承诺及待核问题；不伪造正文结构、案例、两处锚点、收益或传播原因。
- 说明补齐正文/相关媒体后才能做的部分，不把缺口报告写成稳定的完整拆解页；无真实本地 raw 时不创建或改 raw，不虚填 `sources`。
- 已有依据可交付独立的部分分析；需要留库时明确待核实与输入依据，不因无法阅读全文放弃所有可用分析。

**留证**：访问结果、可见输入、部分输出与未核项、实际未写/待核页面清单。

### D. 方法论内部冲突：阅读/转发比例

**输入**：方法论原文第 321—327 行，保留其中比例文字与算例，不预先改写成一致口径。

**应观察到**

- 指出文字中的比值口径与算例不一致，分别定位原文说法，保留冲突；不擅自修正、选边或合成统一阈值。
- 不据此自动判定爆款、自动加热、荐股或承诺投放收益；传播判断仍要求同账号基线、同口径窗口与实际数据。

**留证**：冲突的两处依据、实际解释、未采用阈值和未作因果承诺的输出。

### E. 全新批次工具烟测：真实 CLI 消费契约

**输入与准备**：在另一临时新库复用 `test_batch.py` 的 `RAW_SAMPLE`、`INDEX_TEMPLATE`、维度页及填充方式；分析内容明确标注为合成演练。完整作者目录仅含该样本，全部目标 source/topic/comparison 不存在，检查维度追加段落无冲突。日期参数填写实际执行日期，不将测试夹具中的固定历史日期当作今天。

**执行与判定**

1. 使用技能目录下真实脚本路径运行 `init`，读取 manifest 中的文章编号；准备以这些编号为键、以允许的元数据字段对象为值的 JSON 文件，通过 `meta --batch "<批次目录>" --file "<元数据 JSON 路径>"` 合并到 manifest，并读取合并结果。允许字段为 `title`、`original_title`、`question`、`primary_type`、`primary_product`、`evidence_role`、`own_idea`、`source_page`。随后按夹具方式填充 analyses、作者 topic、comparison 与 dimensions，不改现有 JSON/CLI 契约；所有子命令均保留必需的全局 `--root` 参数。
2. 实际运行 `build` 再 `check`，保留命令、返回码和关键输出；观察 source、作者页、comparison、维度增量、索引和日志确实产生，原 raw 哈希不变。
3. 同批次再次运行 `build`，应保留“拒绝重复追加”的非零退出行为；不把脚本说成幂等或可安全覆盖已有知识。
4. 脚本回归仍检查目录覆盖、原文变动、锚点来源、重复追加拒绝与待测状态，不绑定生成正文的固定免责声明句式。不新增提示词措辞硬编码断言。

**留证**：临时路径、合成声明、完整 CLI 步骤与返回码、实际生成页清单、前后 raw 哈希、第二次 build 拒绝记录。不得将这些合成页面同步到真实 wiki。
